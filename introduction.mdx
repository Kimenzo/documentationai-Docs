## What is Genesis?

Genesis is a React and Vite single-page app for AI-powered visual storytelling and storybook generation. It runs entirely client-side and orchestrates multiple AI providers to turn text prompts into structured, illustrated story experiences.

Genesis does not expose a backend HTTP API or server layer. All data and AI calls happen from the browser using client-side SDKs and provider APIs.

<Callout kind="info">

Genesis is a static single-page application. You deploy it as a static site (for example, on Vercel) with rewrites pointing all routes to `index.html`.

</Callout>

## Core capabilities

Genesis focuses on helping you go from an idea to a visual story using AI for both text and images.

- **Story generation** — Use Gemini or Grok (via OpenRouter) to generate plot outlines, scenes, and narrative text.
- **Visual storytelling** — Generate illustrations for scenes with the Bytez image API and combine them with the narrative.
- **Persistence with Supabase** — Store projects, stories, and assets using Supabase auth and database/storage.
- **Payments with Paystack** — Gate premium features and manage pricing using Paystack on the client.

### How Genesis is wired together

These integrations work together inside the browser to power the app.

<Steps>
  <Step title="Authenticate and load user data" icon="users">

    Genesis uses Supabase in the browser for authentication and project storage. When you sign in, it fetches your saved stories and assets from Supabase tables and storage buckets.

  </Step>

  <Step title="Generate narrative with LLMs" icon="code">

    For each story or scene, Genesis sends prompts to Gemini or Grok through OpenRouter using the configured API keys. The app turns model responses into structured story segments and metadata.

  </Step>

  <Step title="Create images with Bytez" icon="image">

    Once the narrative is ready, Genesis calls the Bytez image API from the client to create illustrations that match each scene. It then stores URLs or image references in Supabase.

  </Step>

  <Step title="Handle billing with Paystack" icon="credit-card">

    When a user upgrades or triggers a paid action, the app talks to Paystack using the public key to handle checkout flows and reflect access state in the UI.

  </Step>
</Steps>

<Callout kind="tip">

Use environment-specific keys (for example, different Supabase and Paystack projects) so you can experiment locally without affecting production data.

</Callout>

## Key integrations and environment variables

Genesis reads its configuration from Vite environment variables. Define these in `.env.local` (based on `.env.example`) before running the app.

<Columns cols={2}>
  <Card title="Supabase (auth and storage)" href="/configuration" icon="database">

    - `VITE_SUPABASE_URL`
    - `VITE_SUPABASE_ANON_KEY`

    Supabase provides authentication, database, and file storage directly from the browser.

  </Card>

  <Card title="LLMs (Gemini and Grok)" href="/configuration" icon="zap">

    - `VITE_GEMINI_API_KEY`
    - `VITE_GROK_API_KEY`

    These keys allow Genesis to send prompts to Gemini and Grok (via OpenRouter) for story and text generation.

  </Card>
</Columns>

<Columns cols={2}>
  <Card title="Images with Bytez" href="/configuration" icon="image">

    - `VITE_BYTEZ_API_KEY`

    Bytez powers image generation for scenes and story panels, returning URLs that the app stores and renders.

  </Card>

  <Card title="Payments with Paystack" href="/configuration" icon="credit-card">

    - `VITE_PAYSTACK_PUBLIC_KEY`

    The Paystack public key enables client-side checkout flows and pricing features.

  </Card>
</Columns>

<Callout kind="info">

All configuration keys use the `VITE_` prefix because Genesis is built with Vite. Vite exposes only variables starting with `VITE_` to the client bundle.

</Callout>

## Run Genesis locally

Start a local development instance to explore the app and contribute changes.

<Steps>
  <Step title="Clone and install dependencies" icon="download">

    Use your preferred Git client to clone the Genesis repository, then install dependencies:

    <CodeGroup tabs="npm,yarn" show-lines={true}>

      ```bash
      npm install
      ```

      ```bash
      yarn install
      ```

    </CodeGroup>

  </Step>

  <Step title="Configure environment variables" icon="settings">

    Copy the example environment file and fill in the required Vite keys:

    ```bash
    cp .env.example .env.local
    ```

    Set values for:

    - `VITE_SUPABASE_URL`
    - `VITE_SUPABASE_ANON_KEY`
    - `VITE_PAYSTACK_PUBLIC_KEY`
    - `VITE_GEMINI_API_KEY`
    - `VITE_GROK_API_KEY`
    - `VITE_BYTEZ_API_KEY`

  </Step>

  <Step title="Start the Vite dev server" icon="play-circle">

    Run the development server:

    ```bash
    npm run dev
    ```

    Vite starts on a local URL such as `http://localhost:5173`. Open that URL in your browser to interact with Genesis.

  </Step>
</Steps>

<Callout kind="info">

Deployment uses static hosting with a rewrite configuration (for example, `vercel.json`) that routes all paths back to `index.html`, preserving client-side routing.

</Callout>
